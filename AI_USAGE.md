# AI Usage Documentation

This document describes how AI assistance (Claude, Anthropic) was used in
producing this project, in the interest of transparency and academic
integrity.

## What AI generated

- **All source code** in `src/` (data acquisition, cleaning, EDA, PCA,
  intrinsic dimension estimation, curse-of-dimensionality diagnostics,
  dimensionality-reduction comparison, random projection, outlier detection)
  was written by Claude, executed in a sandboxed Python environment, and
  iterated on when errors occurred (e.g. a pandas API deprecation in the
  stratified-sampling helper was caught and fixed after a runtime error).
- **All 14 figures** were generated by running that code against the real,
  downloaded dataset — they are not mocked, hand-edited, or illustrative
  placeholders. Every number quoted in the report (e.g. "27 components for
  80% variance," "5.2% of pairs exceed |r|=0.9") was read directly from the
  corresponding table output of the analysis code, not estimated or invented.
- **The report text** (docx/PDF), README, and this AI-usage document were
  drafted by Claude, using the actual numerical results produced by the code
  as the source of every quantitative claim.
- **The presentation slides** were generated by Claude from the same
  analysis outputs.

## What required human verification

- **Dataset choice and framing.** The user specified the dataset (UCI HAR)
  and its rationale (561 features, clean, standard dimensionality-reduction
  benchmark) before analysis began; Claude did not select the dataset
  independently.
- **All numerical results should be independently re-run and spot-checked**
  before submission. Every script in `src/` is deterministic (seed=42) and
  reproducible from the raw UCI data — re-running the pipeline end-to-end is
  the recommended verification step, and will reproduce every figure, table,
  and number cited in the report exactly.
- **Interpretive claims** (e.g. the explanation for why FisherS and local-PCA
  intrinsic-dimension estimates diverge sharply from MLE/TwoNN, or the
  biomechanical explanation for WALKING_DOWNSTAIRS's high outlier rate) are
  Claude's statistically-informed interpretation of the numerical results,
  not independently verified against external ground truth, and should be
  reviewed by the student/instructor for domain plausibility.
- **Citations** were restricted to well-known, real, foundational papers in
  the relevant methods (PCA, t-SNE, UMAP, MLE/TwoNN intrinsic dimension,
  Johnson–Lindenstrauss, LOF, Isolation Forest) and the dataset's own
  citation; these should be verified against the original sources before
  submission, as is good practice for any citation regardless of origin.

## How outputs were validated

1. **Data integrity checks** were run programmatically (missing values,
   duplicate rows, out-of-range values) and their results are reported
   verbatim in Section 2.2 of the report and in
   `data/processed/data_quality_report.txt` — this was not a manual or
   subjective check.
2. **Every figure was visually inspected** after generation (rendered and
   reviewed) before being included in the report, to confirm it matched its
   intended content and caption.
3. **The final report docx was rendered to PDF and visually reviewed
   page-by-page** to confirm correct figure embedding, table formatting, and
   layout before delivery.
4. **Cross-consistency check:** every quantitative claim in the report
   narrative was traced back to a specific CSV table in `report/tables/`
   produced by the analysis code, rather than being paraphrased from memory.

## Recommended student verification steps before submission

- Re-run the full pipeline (`src/data_acquisition.py` through
  `src/outlier_detection.py`) on a clean checkout to confirm reproducibility.
- Read through the Discussion, Limitations, and Future Work sections
  critically — these contain the most interpretive (least purely
  computational) content and benefit most from domain-expert review.
- Verify all references against original sources.
- Confirm the report's claims about *why* the dataset was chosen over the
  alternatives in Section 2 reflect the student's own reasoning, or adjust
  as needed.
